# 성지덕 발표 스크립트 & 시연 흐름

> 목표 시간: **12분** (오프닝 1.5 + 데모 5 + 기술 딥다이브 4 + 확장·비전 1 + 마무리 0.5). 리허설로 조정.
> 원칙: **결과(데모) 먼저, 기술은 "실제로 겪은 문제 → 해결" 서사로.**
> 데모: **QR → 관객 폰에서 직접 실행**(배포판) + 발표자 큰 화면 동시 진행.

> **현재 상태(2026-07-09)**: API 진행률 ~91% · **3장르 15작품**(애니 11·영화 2·소설 1·K-POP 1) · **LangGraph 3개 그래프** · 9단계 여정 8/9 관통(결제 API까지 landed) · 필수 요구사항 5/5 실동작.

## 1. 오프닝 — 쇼케이스 + 문제 정의 (1.5분)

**[화면: 쇼케이스 — 덕식이 스카이다이브 여정 (holymoly.cloud)]**

> "오덕후에게 여행은 관광이 아니라 **순례**입니다. 좋아하는 작품의 '그 장면, 그 장소'를 직접 밟는 것 — 성지순례죠.
> 그런데 기존 여행앱은 폼 채우고 리스트 보는 지루한 경험이라, 팬이 원하는 성지순례를 못 다룹니다. 장소는 블로그에 흩어져 있고, 순서·기간·예산을 실제 일정으로 엮는 건 번거롭죠.
> **성지덕**은 이걸 '성지 데이터 + 지도 + AI'로 풉니다. 작품만 고르면 AI가 **실제로 갈 수 있는 코스**를 짜줍니다."

(스크롤하며 정거장 패널 = 기획/진행률/트러블슈팅 잠깐 노출 → 토리이 도착 → 무한 루프)

| ⑨ 저장·공유·여권 | 로그인 → 저장 → 마이페이지 | "비회원이 만든 일정을 **로그인하면 이어서 저장**(탑승 수속). 마이페이지엔 **작품별 성지 여권**(방문 도장·수집률)." |

## 3. 기술 딥다이브 (4분) — "원칙 하나 + 겪은 문제들"

### 3-0. 아키텍처 원칙 — LLM은 언어, 도구는 계산 (1분)

**[슬라이드: LangGraph 3개 그래프 다이어그램]**

> "AI 서비스는 **LangGraph 상태머신 3개**입니다.
> ① **trip** (filter→constrain→route→language): 일정 생성·대화형 재조정
> ② **route** (extract→aggregate→cluster): 블로그 동선 검증
> ③ **describe**: 설명·미션 생성
> 각 그래프에서 **GPT 노드는 판단·언어(취향 번역·순서 추출·설명)만**, **계산(좌표·이동시간·집계)은 결정론 도구 노드**가 합니다. LLM에 최적화 수학을 시키면 거짓 거리를 지어내니까요. **환각이 좌표를 못 건드리는 구조**입니다." (상세: 06 문서)

### 3-1. 차별화 — 블로그로 "검증된 동선" 만들기 (1분)

> "성지 순서를 AI가 상상하면 신뢰가 안 갑니다. 그래서 **실제 후기로 검증**합니다.
> 네이버 검색 API로 후기 수집 → 본문 1회 조회(**원문 미저장, 저작권**) → GPT가 방문 순서 추출 + **실방문 후기인지 게이트**(뉴스·감상평 차단) → **방향 무시 연속쌍 합의 클러스터링** → 코스.
> 실측: 후기 12건 중 게이트를 통과한 것만 모아, **여러 명이 독립적으로 같은 순서로 간 코스**를 뽑았습니다. 이게 '데이터 3단 진화'(Anitabi→블로그 합의→우리 유저 VisitRecord)의 두 번째 단계예요."

### 3-2. AI 모델, 뭐가 최선일까 — 실측 비교 (0.7분)

| 모델 | 품질 (같은 프롬프트) | 정책 |
|---|---|---|
| gpt-4o-mini | "소중한 추억을 쌓는 장소" — 어디에나 붙는 문장 | ✕ |
| **gpt-4o ✅** | 칸다묘진=결성·연습 장면, 카피로 자연스러움 | 라이브 기본 |
| gpt-5.5 | **"μ's 훈련 계단", "노조미 무녀 인연"** — 덕후 전문가급 | 프리웜 후보 |

> "재밌는 건, 처음엔 5.5가 mini보다 못했어요. 환각 막으려 '주어진 정보에만'이라 했더니 5.5가 자기 지식까지 봉인하고 '정보 없음'을 화면에 뱉었죠. 프롬프트를 '아는 건 활용, 불확실한 세부만 생략'으로 바꾸자 위 품질이 나왔습니다. **제약은 모델 능력에 맞춰 조정**해야 한다는 교훈." (ADR-0004)

### 3-3. GPT 비용이 2배로 새고 있었다 — single-flight (0.7분)

> "캐시가 비는 첫 순간 동시 요청이 오면 둘 다 미스로 GPT를 두 번 부릅니다(React StrictMode가 상시 재현). **작품별 락 + 락 후 캐시 재확인**으로 첫 요청만 GPT를 부르게 했어요. 동시성 테스트로 RED 먼저, 실측 2회→1회. **1차 66초→2차 0.05초, 비용 절반.**" (ADR-0005)

### (시간 남으면) 3-4. mock이 절대 못 잡는 버그 — h2c body 유실

> "Java backend가 Python ai-service를 부르는데 body가 통째로 사라져 422. 범인은 평문 http의 **HTTP/2 업그레이드(h2c)** — HTTP/1.1 강제로 해결. 단위 테스트 100+개가 초록이어도 못 잡습니다(mock은 HTTP를 안 타니까). 그래서 **통합 지점마다 실통신 E2E 강제**가 원칙입니다."

## 4. 데이터·확장성 (0.5분)

> "성지 데이터는 **Anitabi**(CC BY-NC-SA — 출처 표기·이미지 핫링크만) 부트스트랩. 여기에 **Wikidata**(영화 촬영지)·**한국관광공사 TourAPI**(K-POP 성지)를 더해 **3개 소스 × 4장르**로 확장했습니다. '일본 애니 전용'이 아니라 **콘텐츠 성지순례 플랫폼**이라는 증명이에요." (ADR-0002)

## 5. 확장·비전 + 마무리 (1분)

> "정리하면 성지덕은 ① 실데이터 파이프라인 ② 역할 분리 AI 레이어(검증·설명·일정) ③ 비용·안정성 장치(캐시·single-flight·폴백)까지 **끝에서 끝까지 실제로 도는** 성지순례 플래너입니다. 필수 요구사항 5개 전부 실동작하고요.
>
> 여기서 끝이 아니라 — **검증된 루트는 여행사에 파는 상품 템플릿**(B2B)이 되고, 현장에선 **Quest 3 AR로 그 자리에 애니 장면을 재현**, **최애 캐릭터가 MetaHuman 가이드**로 설명(캐릭터 보이스 TTS), 셀피는 **GPT로 캐릭터를 합성해 SNS 자동 업로드**까지 이어집니다.
>
> **웹에서 계획하고, VR로 미리 가보고, 현장에선 작품 속으로 들어가는 — 하나의 몰입형 성지순례 경험.** 감사합니다."

## 예상 Q&A

| 질문 | 답변 요지 |
|---|---|
| 크롤링/저작권? | 네이버·Anitabi **공식 API만**. 블로그 본문은 1회 조회해 **구조만 추출·원문 미저장**, 이미지는 핫링크. CC BY-NC-SA 준수(ADR-0002). |
| GPT가 잘못된 장소 안내하면? | 좌표·순서·이동시간은 **도구 노드(코드)**가 결정, LLM은 문장만. 후보는 DB의 실제 성지만 — **장소 생성 금지**. 출처 링크로 사용자 검증 가능. |
| 이동시간이 실제 맞나? | 일본 대중교통은 구글 API가 데이터 미제공 → **거리 기반 결정론 모델** 근사. Directions 열리는 지역은 API로 교체(모델 함수만 교체). |
| AI 비용 관리? | 성지별 캐시 + single-flight로 중복 제거, 라이브=4o/테스트=mock(무비용). |
| 결제는? | **결제 API(주문·거래·공급사 예약 상태)는 구현됨**(⑨). 실 PG 연동은 법·계약 이슈로 데모에선 골격까지. |
| 진행률 91%, 나머지는? | 미완은 ③숙소(외부 예약 API 대기)·관리자 delete(mock)·제보 영속화 정도. **코어 여정은 관통**. |
| 왜 AI를 분리했나? | LangGraph 생태계가 Python 중심(ADR-0001). **장애 격리** — AI가 죽어도 backend는 폴백(로컬 배치·설명 null)으로 동작. |
| 테스트 전략? | 백엔드 100+개 BDD(TDD, RED→GREEN 커밋 분리) + 통합 지점 실통신 E2E. mock만으론 h2c 같은 버그를 못 잡아서. |
