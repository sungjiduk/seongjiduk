# 13. 클래스 다이어그램

> 제출물: Class Diagram. 실제 코드(`repositories/seongjiduk-backend`, dev 기준 워킹트리)의 `@Entity`를 그대로 읽어 작성했다 — 04 ERD가 "계획"이라면 이 문서는 "구현 실측"이다. Mermaid로 관리하고 PNG는 `../발표자료/assets`로 export한다.

## 1. 엔티티 클래스 다이어그램

JPA 엔티티 18개 + Redis 해시 1개(RefreshToken). 도메인별로 사용자 / 콘텐츠·성지 / 여행 / 결제·예약 / 기록·로그 5개 그룹으로 나눴다.

설계 포인트:
- **다형 FK 회피**: `TripStop`은 `pilgrimageSpotId`·`nearbyAttractionId` 두 컬럼을 모두 갖고 `spotType` enum으로 어느 쪽을 쓰는지 구분한다(둘 중 하나만 채움 — DB CHECK + 애플리케이션 검증). 하나의 FK 컬럼이 두 테이블을 가리키는 다형 FK를 피한 설계.
- **소프트 참조**: `AiRequestLog.tripPlanId`, `UsageEvent.userId`는 FK 제약 없이 id만 보관 — 일정/회원이 삭제돼도 통계 원천 데이터는 보존된다.
- **비회원 허용**: `TripPlan.user`, `AiRequestLog.user`는 null 허용(비회원 일정 생성) → 로그인 시 `assignOwner()`로 소유권 이관.
- 04 ERD에 있던 `UserFavoriteContent`·`SpotReport`·`BookingLink`는 엔티티로 구현되지 않았다(제보는 관리자 DTO 플로우, 예약 링크는 결제 도메인 `TravelOffer`로 대체).

```mermaid
classDiagram
    direction LR

    %% ===== 공통 (MappedSuperclass) =====
    class BaseEntity {
        <<abstract>>
        +LocalDateTime createdAt
        +LocalDateTime updatedAt
        +LocalDateTime deletedAt
    }

    %% ===== 사용자 도메인 =====
    class User {
        +Long id
        +String email UK
        +String passwordHash
        +String nickname
        +Role role
    }
    class UserPreference {
        +Long id
        +User user
        +String travelStyle
        +String budgetLevel
    }
    class RefreshToken {
        <<RedisHash>>
        +String refreshToken
        +String email
        +Long ttl
    }

    %% ===== 콘텐츠·성지 도메인 =====
    class Content {
        +Long id
        +String title
        +String category
        +String country
        +String description
    }
    class PilgrimageSpot {
        +Long id
        +Content content
        +String name
        +String address
        +BigDecimal lat
        +BigDecimal lng
        +String city
        +Integer recommendedDurationMin
    }
    class SpotReference {
        +Long id
        +PilgrimageSpot spot
        +String title
        +String url
        +String sourceName
    }
    class NearbyAttraction {
        +Long id
        +String name
        +String category
        +BigDecimal lat
        +BigDecimal lng
        +String mapsUrl UK
    }
    class SpotMission {
        +Long id
        +PilgrimageSpot spot
        +String title
        +MissionType missionType
        +MissionOrigin origin
        +boolean active
    }

    %% ===== 여행 도메인 =====
    class TripPlan {
        +Long id
        +User user 비회원이면_null
        +Content content
        +String title
        +int durationDays
        +TripStatus status
        +String shareToken UK
    }
    class TripDay {
        +Long id
        +TripPlan tripPlan
        +int dayNo
        +String summary
    }
    class TripStop {
        +Long id
        +TripDay tripDay
        +SpotType spotType
        +Long pilgrimageSpotId
        +Long nearbyAttractionId
        +int sequence
        +String arrivalTime
        +int stayMinutes
    }
    class TripStatus {
        <<enumeration>>
        DRAFT
        SAVED
    }
    class SpotType {
        <<enumeration>>
        PILGRIMAGE
        ATTRACTION
    }

    %% ===== 결제·예약 도메인 =====
    class TravelOffer {
        +Long id
        +TripPlan tripPlan
        +TravelOfferProvider provider
        +TravelOfferType offerType
        +String name
        +Long price
        +LocalDateTime validUntil
    }
    class PaymentOrder {
        +Long id
        +User user
        +TripPlan tripPlan
        +String orderId UK
        +Long totalAmount
        +PaymentOrderStatus status
    }
    class PaymentOrderItem {
        +Long id
        +PaymentOrder paymentOrder
        +TravelOffer travelOffer
        +String itemName 스냅샷
        +TravelOfferType itemType
        +Long amount
    }
    class PaymentTransaction {
        +Long id
        +PaymentOrder paymentOrder
        +String paymentKey UK
        +PaymentTransactionStatus status
        +Long amount
        +String rawPayload
    }
    class SupplierBooking {
        +Long id
        +PaymentOrder paymentOrder
        +TravelOfferProvider provider
        +String externalReservationId
        +SupplierBookingStatus status
        +Long paidAmount
    }

    %% ===== 기록·로그 도메인 =====
    class VisitRecord {
        +Long id
        +User user
        +PilgrimageSpot spot
        +TripPlan tripPlan 일정없이도_null허용
        +String note
        +String imageUrl
        +LocalDateTime visitedAt
    }
    class AiRequestLog {
        +Long id
        +User user 비회원이면_null
        +Long tripPlanId 소프트참조
        +AiRequestType requestType
        +AiRequestStatus status
        +Integer tokenUsage
    }
    class UsageEvent {
        +Long id
        +Long userId 소프트참조
        +EventType eventType
        +String path
        +String sessionId
        +LocalDateTime occurredAt
    }

    %% ===== 상속 (BaseEntity 감사 필드) =====
    BaseEntity <|-- User
    BaseEntity <|-- TravelOffer
    BaseEntity <|-- PaymentOrder
    BaseEntity <|-- PaymentOrderItem
    BaseEntity <|-- PaymentTransaction
    BaseEntity <|-- SupplierBooking

    %% ===== 사용자 관계 =====
    User "1" --> "N" UserPreference : 선호 정보
    User "1" --> "N" TripPlan : 일정 생성
    User "1" --> "N" VisitRecord : 방문 인증
    User "1" --> "N" AiRequestLog : AI 호출
    User "1" --> "N" PaymentOrder : 결제 주문
    RefreshToken ..> User : email로 연결

    %% ===== 콘텐츠·성지 관계 =====
    Content "1" --> "N" PilgrimageSpot : 성지 포함
    Content "1" --> "N" TripPlan : 일정 대상
    PilgrimageSpot "1" --> "N" SpotReference : 근거 링크
    PilgrimageSpot "1" --> "N" SpotMission : 미션
    PilgrimageSpot "1" --> "N" VisitRecord : 방문 대상

    %% ===== 여행 관계 (cascade + orphanRemoval 컴포지션) =====
    TripPlan "1" *-- "N" TripDay : 일자별 구성
    TripDay "1" *-- "N" TripStop : 방문 장소
    TripPlan "1" --> "N" VisitRecord : 일정 내 방문
    TripStop --> TripStatus
    TripStop --> SpotType

    %% ===== 다형 FK 회피: TripStop은 두 id 컬럼 + spotType으로 분기 =====
    TripStop ..> PilgrimageSpot : pilgrimageSpotId (spotType=PILGRIMAGE)
    TripStop ..> NearbyAttraction : nearbyAttractionId (spotType=ATTRACTION)

    %% ===== 결제·예약 관계 =====
    TripPlan "1" --> "N" TravelOffer : 항공권·숙소 후보
    TripPlan "1" --> "N" PaymentOrder : 결제 대상
    PaymentOrder "1" *-- "N" PaymentOrderItem : 주문 항목
    PaymentOrder "1" *-- "N" PaymentTransaction : PG 거래 기록
    PaymentOrder "1" *-- "N" SupplierBooking : 공급자 예약
    PaymentOrderItem "N" --> "1" TravelOffer : 가격 스냅샷 원본

    %% ===== 로그 소프트 참조 =====
    AiRequestLog ..> TripPlan : tripPlanId (FK 없음 - 통계 보존)
    UsageEvent ..> User : userId (비회원 null)
```

## 2. 서비스 레이어 아키텍처

주요 4개 도메인(Trip / Spot·RouteVerification / Content / Auth)의 Controller → Service → Repository·Infra 흐름과, §7 가드 인터페이스의 **mode 토글 패턴**(설정값 하나로 Redis/InMemory/NoOp 구현체 교체 — `RateLimitConfig`, `RouteCacheConfig`가 조립)을 보여준다.

```mermaid
classDiagram
    direction TB

    %% ===== Controller 계층 =====
    class TripController
    class SpotController
    class ContentController
    class AuthController

    %% ===== Service 계층 =====
    class TripService {
        +generate() AI 일정 생성
        +save() / share()
    }
    class SpotService {
        +nearbyAttractions()
        +streetView()
    }
    class RouteVerificationService {
        +verify(contentId) 검증 신뢰도
    }
    class ContentService {
        +list() / describe()
    }
    class AuthService {
        +signup() / login() / reissue()
    }

    %% ===== Repository·Infra 계층 =====
    class TripPlanRepository
    class PilgrimageSpotRepository
    class ContentRepository
    class UserRepository
    class RefreshTokenRepository {
        Redis
    }
    class AiTripClient {
        ai-service 호출
    }
    class GooglePlacesProvider
    class NaverBlogClient
    class AiRouteVerifyClient

    %% ===== §7 가드 인터페이스 (mode 토글) =====
    class RateLimiter {
        <<interface>>
        +tryAcquire(key, limit, window) bool
    }
    class RedisRateLimiter
    class InMemoryRateLimiter
    class NoOpRateLimiter

    class ConcurrencyLimiter {
        <<interface>>
        +acquire(key, max, wait) Permit
    }
    class RedisConcurrencyLimiter
    class InMemoryConcurrencyLimiter
    class NoOpConcurrencyLimiter

    class RouteVerificationCache {
        <<interface>>
        +get(contentId)
        +put(contentId, response, ttl)
    }
    class RedisRouteVerificationCache
    class InMemoryRouteVerificationCache

    %% ===== Controller → Service =====
    TripController --> TripService
    SpotController --> SpotService
    ContentController --> ContentService
    ContentController --> RouteVerificationService
    AuthController --> AuthService

    %% ===== Service → Repository / Infra =====
    TripService --> TripPlanRepository
    TripService --> AiTripClient
    TripService --> ContentService
    TripService --> RouteVerificationService
    SpotService --> PilgrimageSpotRepository
    SpotService --> GooglePlacesProvider
    ContentService --> ContentRepository
    ContentService --> PilgrimageSpotRepository
    RouteVerificationService --> NaverBlogClient
    RouteVerificationService --> AiRouteVerifyClient
    RouteVerificationService --> RouteVerificationCache
    AuthService --> UserRepository
    AuthService --> RefreshTokenRepository

    %% ===== Infra → 가드 (외부 API 앞단 수도꼭지) =====
    AiTripClient --> RateLimiter
    AiTripClient --> ConcurrencyLimiter
    GooglePlacesProvider --> RateLimiter
    NaverBlogClient --> RateLimiter

    %% ===== mode 토글: 구현체 3종 (redis / local / off) =====
    RateLimiter <|.. RedisRateLimiter : mode=redis
    RateLimiter <|.. InMemoryRateLimiter : mode=local
    RateLimiter <|.. NoOpRateLimiter : mode=off
    ConcurrencyLimiter <|.. RedisConcurrencyLimiter : mode=redis
    ConcurrencyLimiter <|.. InMemoryConcurrencyLimiter : mode=local
    ConcurrencyLimiter <|.. NoOpConcurrencyLimiter : mode=off
    RouteVerificationCache <|.. RedisRouteVerificationCache : mode=redis
    RouteVerificationCache <|.. InMemoryRouteVerificationCache : mode=local
```

### 설계 메모

| 항목 | 내용 |
|------|------|
| 계층 규칙 | Controller는 Service만 호출, Service가 Repository·Infra(외부 API 클라이언트)를 조합 |
| §7 가드 | 외부 API(OpenAI·Google·Naver) 호출 직전 `RateLimiter`(고정 윈도우), AI 일정 생성 앞단 `ConcurrencyLimiter`(세마포어+대기열) |
| mode 토글 | `RateLimitConfig`·`RouteCacheConfig`가 프로퍼티(mode) 값으로 Redis(운영·분산) / InMemory(로컬 단일 인스턴스) / NoOp(끔) 구현체를 골라 주입 — 코드 수정 없이 환경별 전환 |
| Redis 사용처 | RefreshToken 저장(TTL 자동 만료), 분산 레이트리밋/세마포어, 검증 결과 캐시(장애 시 fail-open) |
