# 13. 시네마틱 여정 + 퀘스트 설계

> 최종 생성된 일정을 three.js 로우폴리 카툰 디오라마로 보여주는 "시사회" 화면과,
> 이를 게임 루프로 만드는 스팟 미션(퀘스트) 도메인의 설계 문서.
> 결정일: 2026-07-09 (스케치 2장 + 로우폴리 레퍼런스 기반 브레인스토밍)

## 0. 목적·확정 결정

| 결정 | 내용 |
|------|------|
| 용도 | **발표 데모 우선, 제품 편입 전제** — MVP는 데모 기준 연출, 구조는 제품 대비 |
| 일정 | 2주+ — 풀 스케치 스코프(퀘스트 포함), 신 단위로 완성 누적 |
| 퀘스트 | **정식 도메인 승격** — `SpotMission` 엔티티. AI 초안 생성 + 관리자 검수 |
| 조작 | **스크롤 스크럽 + 자동진행**(스크롤 값 트윈) 처음부터 동시 |
| 세계 | **지구본 인트로 + 떠 있는 로우폴리 섬 디오라마** (파스텔 카툰 톤) |
| 미학 | 로우폴리 3D 카툰 — 파스텔 그라데이션 하늘, 낮은 채도 소품, 떠 있는 섬 |

## 1. 신(Scene) 구성 — 스크롤 타임라인

| # | 신 | 내용 | 재료 |
|---|-----|------|------|
| S0 | 오프닝 | 지구본 위 비행기 이륙 → 목적지 국가 회전·줌인 | 기존 지구본 히어로 재활용 |
| S1 | 구름 다이브 | 구름층 뚫고 하강 | showcase-v2 구름 에셋 이식 |
| S2 | Day 섬 등장 | 로우폴리 섬 조립 연출(소품 솟아오름) → 핀 순차 드랍 | IslandBuilder |
| S3 | 스팟 다이브 ×N | 카메라 핀 접근 → 장면컷 패널 + 미션 카드(+맛집·팁 1패널) | sceneImageUrl·미션 API |
| S4 | 이동 연출 | 스팟 간 점선 경로 따라 카메라·미니 기차 | 경로 = 일정 순서 |
| S5 | Day 전환 | 섬 이륙 → 구름 → 다음 Day 섬 (일수만큼 반복) | S1 재활용 |
| S6 | 엔딩 | 전체 섬 부감 → 여권 도장 쾅 → CTA(저장·여권 보기) | 성지여권 도장 모티프 |

## 2. 프론트 아키텍처 (seongjiduk-frontend)

- **`TripCinematic`** — 별도 lazy 청크(진입 시에만 three.js 로드). 데모=직행, 제품=TripResult "시사회 보기" 버튼.
- **`useScrollTimeline`** — showcase-v2 감쇠 보간 스크럽 이식 + 자동진행(스크롤 값을 GSAP 트윈으로 구동).
- **`IslandBuilder`** — 스팟 실좌표(lat/lng)의 **상대 위치를 정규화**해 섬 위 배치. 소품(나무2·바위·산·건물·토리이 GLB, meshopt)은 `seed=contentId` 결정적 프로시저럴 배치 → 전 작품 호환·재현 가능.
- **`PanelAnchor`** — 3D→2D 프로젝션으로 **DOM 패널** 앵커링. 패널은 HTML + v2 디자인 토큰(코럴/웜톤) 그대로.
- 데이터: **TripResult가 받는 응답 재사용**(추가 fetch 없음) + 미션 API + 장면컷/실거리뷰 기존 API.
- 폴백 게이트: WebGL 미지원·prefers-reduced-motion → 기존 TripResult. 모바일 최적화는 제품 편입 단계.

## 3. 미션(퀘스트) 도메인 (seongjiduk-backend + seongjiduk-ai)

- 엔티티 **`SpotMission`**: `id · spot FK · title · description · missionType(FIND/PHOTO/TASTE/…) · origin(AI/ADMIN) · active`
  - ⚠️ **새 테이블 `spot_missions` → A파트 Flyway 조율 목록 등재**(visit_record·ai_request_log와 같은 트레인).
- 생성 파이프라인: **describe 확장** — ai-service 구조화 출력에 `missions` 필드(스팟당 1~3개), 임포트/프리웜 때 초안 자동 저장.
- 조회: **`GET /api/contents/{id}/missions`** — 작품 단위 일괄(스팟별 그룹). 시네마틱 진입 시 1왕복으로 전 스팟 미션 확보(스팟별 개별 호출 N+1 배제).
- 달성: `POST /api/missions/{id}/complete` → **기존 VisitRecord 재사용**으로 방문 기록 + 여권 도장 실반영.
- 관리자: 기존 admin 스팟 CRUD에 미션 목록·수정·삭제(검수). 데모 전 러브라이브 1작품 검수.

## 4. 구축 순서

1. **1주차 — 관통 골격**: 스크럽 타임라인 + 섬 1개 + 핀 드랍 + 카메라 패스 + 장면컷 패널. 러브라이브 시나리오 끝까지 관통 최우선. 미션 백엔드 병행 스택 PR(엔티티→AI 생성→API→admin).
2. **2주차 — 연출 완성**: 지구본 인트로·구름 전환·이동 연출·도장 엔딩·미션 체크인 연동.
3. **마감 주**: 자동진행·사운드·데모 리허설(발표 머신 GPU 확인).
4. **발표 후(제품 편입)**: 모바일·성능 예산·TripResult 토글 정식화.

## 5. 리스크·미결

- 소품 GLB 조달: 직접 제작 vs 무료 에셋(라이선스 확인 필수) — showcase-v2 방식 답습.
- AI 미션 문구 품질 → 관리자 수정으로 커버, 러브라이브 우선 검수.
- 스케치 중 **데이터 없는 요소는 스코프 아웃**: 교통편 추천(Routes TRANSIT 일본 미지원 → 거리 기반 이동시간 표기로 대체), 날씨(미구현), 숙소(Rakuten 키 대기 → 실거리뷰로 치환).
- 발표 머신 성능 — 리허설 필수.
