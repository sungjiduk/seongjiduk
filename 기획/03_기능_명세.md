# 03. 기능 명세

> 요구사항 5대 필수 영역 기준. 각 기능에 ID를 부여하고 API/ERD와 교차참조한다.

## F-1. 회원 기능

### F-1-1. 회원가입
- 자체 회원가입/로그인 방식 사용
- OAuth 2.0은 MVP 범위에서 제외
- 필수 입력: 이메일, 비밀번호, 닉네임
- 선택 입력: 선호 작품, 선호 장르, 선호 여행 스타일

### F-1-2. 로그인/로그아웃
- Spring Security 기반 인증/인가 적용
- 인증 방식은 JWT 우선 검토
- 비회원도 일정 생성은 가능하지만, 저장/공유/개인화 기능은 회원만 사용 가능

### F-1-3. 권한
- USER: 일정 생성, 저장, 공유, 방문 기록
- ADMIN: 관리자 통계, 성지 데이터 관리

## F-2. 데이터 영속화

### 영속화 대상
- 회원
- 작품/콘텐츠
- 성지 스팟
- 주변 일반 관광 스팟
- 여행 조건
- 여행 일정
- 일정 상세 장소
- 방문 인증/메모
- 성지 제보
- AI 호출 로그
- 접속/이용 통계 이벤트

### DB
- PostgreSQL 우선
- 지도/거리 계산은 MVP에서 mock 좌표 기반
- 실제 지도 API 및 외부 예약 API는 2차 범위

## F-3. 사용자 UI

### 화면 목록
| 화면 | 설명 |
|------|------|
| 지도 기반 메인 | 첫 화면. 지도와 작품 선택 필터 표시 |
| 작품 선택 | MVP에서는 러브라이브! 뮤즈 중심 |
| 조건 선택 | 여행 기간, 예산, 출발지 선택 |
| 루트 결과 | Day별 일정, 지도 경로, 예상 체류 시간 |
| 루트 수정 | 추가/제외 스팟 선택 후 AI 재생성 |
| 일정 상세 | 장소별 설명, 주소, 레퍼런스 링크, 추천 이유 |
| 회원가입/로그인 | 자체 계정 기반 인증 |
| 마이페이지 | 저장한 일정, 방문 기록, 선호 정보 |
| 공유 화면 | 일정 공유 링크 또는 공유용 텍스트 |
| 관리자 대시보드 | 접속자/서비스 이용 통계 |
| 관리자 성지 관리 | 성지 시드 데이터 등록/수정/삭제 |

### UX 원칙
- 사용자는 최소 입력으로 시작한다: 작품 -> 일정 -> 예산 -> 출발지
- 단계형 설문보다 지도와 필터를 함께 보여준다.
- 사용자가 앞뒤 단계를 오가며 피로를 느끼지 않도록 같은 화면에서 조건 변경과 결과 비교가 가능해야 한다.

## F-4. AI 에이전트 기능 (LangGraph)

### 기능 유형
- [x] 여행 일정 생성
- [x] 일정 재조정
- [x] 추천 이유 생성
- [x] 공유용 요약 문구 생성
- [ ] 실시간 예약 연동

### 입력
- 작품 ID
- 여행 기간
- 예산 태그
- 출발지
- 선택 스팟
- 제외 스팟
- 여행 스타일

### 출력
- Day별 여행 일정
- 방문 순서
- 장소별 추천 체류 시간
- 추천 이유
- 예산 태그 기준 안내
- 공유용 요약 문구

### 백엔드 ↔ ai-service 연동
- 백엔드가 사용자 조건과 후보 스팟 목록을 ai-service로 전달
- ai-service는 LangGraph로 루트 생성/재조정
- 백엔드는 결과를 저장하고 사용자에게 반환

## F-5. 관리자 기능

### F-5-1. 접속자 통계
- 일자별 방문 수
- 일자별 회원가입 수
- 일자별 로그인 수
- 비회원/회원 일정 생성 비율

### F-5-2. 서비스 이용 통계
- 일정 생성 수
- AI 호출 수
- 인기 작품
- 인기 도시/국가
- 인기 성지 스팟
- 평균 여행 기간
- 예산 태그 분포
- 저장/공유 수

### F-5-3. 성지 데이터 관리
- 작품 등록/수정/삭제
- 성지 스팟 등록/수정/삭제
- 레퍼런스 링크 관리
- 사용자 제보 확인 및 반영

## F-6. 예약/외부 링크

### MVP
- 항공권/숙소 직접 예약은 제외
- 일정 상세에서 외부 예약 링크 또는 검색 키워드 제공

### 추후
- 항공권/숙소 API 연동
- 구매/예약 플로우
- 공동 구매 또는 동행 모집
