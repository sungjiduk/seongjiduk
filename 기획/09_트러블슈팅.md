### [2026-07-07] 동시 요청이 GPT를 중복 호출 (비용 2배)
- **증상**: 성지 목록 첫 조회 시 ai-service 로그에 describe 요청이 2회 찍힘. React StrictMode(dev)의 이중 fetch로 상시 재현, 동시 사용자에서도 동일 구조.
- **원인**: 캐시가 비어 있을 때 동시 요청이 모두 캐시 미스 → 각자 GPT 호출. 읽기 경로에 동시성 가드 없음.
- **해결**: 작품별 락 + 락 획득 후 캐시 재확인(single-flight, backend #39). 두 번째 요청은 대기 후 캐시를 읽어 응답에도 설명 포함. 라이브 실측: fetch 2회 → describe 수신 1회.
- **배운 점/재발 방지**: 느리고 비싼 외부 호출 앞에는 캐시만으로 부족 — cold-cache 동시성까지 봐야 한다. "건너뛰기"식 가드는 두 번째 응답이 빈 값이 되는 함정(StrictMode에선 그게 화면에 남음).

### [2026-07-07] GPT 설명이 일본어로 출력됨 (언어 드리프트)
- **증상**: 성지 카드 일부 설명이 일본어("このとんかつ屋さんは…")로 렌더. 한국어 카드에도 일본식 마침표(。) 혼입.
- **원인**: 입력의 장소명이 전부 일본어라 모델이 출력 언어를 끌려감. 프롬프트의 "한국어로" 한 마디로는 부족.
- **해결**: 프롬프트에 언어 고정 명시(ai #2) — "반드시 한국어 문장, 고유명사만 원어 허용, 일본어 문장·。 금지". 브라우저 전수 검사로 34/34 한국어·。 0건 확인.
- **배운 점/재발 방지**: 다국어 데이터를 다룰 땐 출력 언어를 명시적으로 고정하고, **렌더된 화면 기준으로 전수 검증**할 것 (API 응답 샘플 몇 개로는 놓친다 — 이번에도 이중 호출 중 두 번째 응답에서만 발생).

### [2026-07-07] 상위 모델(gpt-5.5)이 하위 모델보다 나쁜 답을 냄
- **증상**: gpt-5.5가 "구체적인 장면 정보가 제공되지 않았으므로…" 같은 헤징 문구만 생성. 같은 프롬프트에서 4o보다 못한 결과.
- **원인**: 프롬프트의 "주어진 정보에만 근거하라"는 환각 방지 제약을 5.5가 **너무 충실히** 준수 → 자기 작품 지식까지 봉인 + 메타 코멘트가 사용자 화면에 노출.
- **해결**: 프롬프트 완화(ai #2) — "아는 지식은 적극 활용, 불확실한 세부만 생략, 메타 코멘트 금지". 튜닝 후 5.5는 "μ's의 훈련 계단·노조미 무녀 설정"급 정확도로 급상승.
- **배운 점/재발 방지**: 프롬프트 제약은 모델 능력에 맞춰 조정해야 한다. 모델 업그레이드 전 프롬프트 재평가 필수. 상세: ADR-0004.

### [2026-07-07] Flyway 마이그레이션이 "없는 테이블" ALTER로 기동 실패
- **증상**: backend 기동 시 `V4__trip_stop_ai_fields.sql` 실패 — `Table 'trip_stop' doesn't exist`.
- **원인**: `ddl-auto: create-drop` 상태에서 직전 종료 때 Hibernate가 테이블을 전부 드롭했는데 `flyway_schema_history`는 남음 → 새 마이그레이션(V4)이 드롭된 테이블을 ALTER 시도. **create-drop과 Flyway는 공존 불가** — 새 마이그레이션이 추가될 때마다 재발.
- **해결(임시)**: `DROP DATABASE` 후 재기동으로 우회. **근본 해결 = A파트 엔티티용 마이그레이션 확보 후 `ddl-auto: validate` 복원** (조율 중, 시급).
- **배운 점/재발 방지**: 스키마 관리 주체는 하나여야 한다(Flyway 단일화). 편의로 켠 create-drop은 마이그레이션이 쌓이는 순간 지뢰가 된다.

### [2026-07-06] Java HTTP 클라이언트 → FastAPI(uvicorn) 요청 body 유실 (422)
- **증상**: backend가 ai-service를 호출하면 422 `body Field required` — body 없이 도착. curl로 같은 페이로드는 200.
- **원인**: Spring `RestClient` 기본 팩토리(JDK HttpClient)가 평문 http에 **HTTP/2 업그레이드(h2c)** 를 시도 → uvicorn(h11)이 거부(`Unsupported upgrade request` 로그)하며 body 유실.
- **해결**: ai-service 호출 클라이언트에 **HTTP/1.1 강제** (`JdkClientHttpRequestFactory` + `HttpClient.Version.HTTP_1_1`). AiDescribeClient(#35)·AiTripClient(#34) 모두 적용. ai-service에 422 로깅 핸들러 추가로 원인 특정.
- **배운 점/재발 방지**: **평문 http로 uvicorn(Python ASGI)에 붙는 모든 Java 클라이언트의 공통 함정.** mock 테스트로는 절대 못 잡는다 — 통합 지점은 반드시 실통신으로 1회 검증.

### [2026-07-06] 34개 스팟 LLM 일괄 호출 → 타임아웃 → 전체 mock 폴백
- **증상**: 성지 34곳 설명 요청이 61초 걸린 뒤 전부 mock 템플릿 문구로 반환(GPT인데 mock처럼 보임).
- **원인**: 34개를 structured-output 1회로 요청 → LLM 타임아웃(30s)×재시도 2회 → 전체 폴백. all-or-nothing 구조.
- **해결**: 청크 분할(8개 단위, env `AI_DESCRIBE_CHUNK`) + **실패한 청크만** 부분 폴백(ai #1).
- **배운 점/재발 방지**: LLM 배치는 타임아웃 예산에 맞춰 분할. 폴백은 부분 단위로 설계해야 한 번의 실패가 전체를 망치지 않는다.

### [2026-07-06] CI에서만 pytest ModuleNotFoundError
- **증상**: 로컬 `python -m pytest` 통과, CI `pytest`는 `No module named 'main'`으로 수집 실패.
- **원인**: `python -m pytest`는 CWD를 sys.path에 넣지만 `pytest` 직접 실행은 아님 → 루트 모듈 import 불가.
- **해결**: repo 루트에 `conftest.py` 추가(루트를 sys.path에 삽입).
- **배운 점/재발 방지**: 로컬과 CI의 실행 커맨드를 일치시키거나, conftest/pyproject(`pythonpath`)로 명시. "로컬은 되는데 CI만 깨짐"은 대부분 실행 컨텍스트 차이.

### [2026-07-06] Nominatim 공개 서버 403 (역지오코딩 차단)
- **증상**: 좌표→주소 변환에 Nominatim 공개 서버 사용 시 403.
- **원인**: 공개 서버 사용 정책(대량/자동화 요청 차단).
- **해결**: 역지오코딩을 스위처블 인터페이스로 — Google(키 옵션) + 실패 시 작품 city 폴백. 임포트는 주소 없이도 항상 성공하게 설계.
- **배운 점/재발 방지**: 무료 공개 API는 사용 정책부터 확인. 외부 의존은 "없어도 동작"이 기본값이 되게 폴백을 먼저 설계.
