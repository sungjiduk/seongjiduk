# 02. 최종 기획서

## 1. 서비스 개요

| 항목 | 내용 |
|------|------|
| 팀명 | 성지덕 |
| 서비스명 | 성지덕 |
| 한 줄 소개 | 오덕후를 위한 성지순례 기반 AI 여행 플래너 |
| MVP 타깃 | 애니메이션 코어 팬 |
| 확장 타깃 | 아이돌 팬, 게임 팬, 영화/드라마 팬 |
| 대표 데모 콘텐츠 | 러브라이브! 뮤즈 성지순례 |
| 확장 예시 | BTS 국내 성지순례 |

성지덕은 사용자가 좋아하는 작품을 선택하면 지도에 실제 성지순례 스팟을 표시하고, 여행 기간/예산/스타일에 맞춰 AI가 성지 중심 여행 루트를 생성해주는 서비스다.

초기 화면은 지도 중심으로 구성한다. 사용자는 긴 설문을 작성하지 않고 `작품 선택 -> 일정 선택 -> 예산 선택`의 최소 입력만으로 1차 추천 루트를 확인한다. 이후 사용자가 추가로 가고 싶은 스팟을 선택하면 AI가 일정을 다시 최적화한다.

## 2. 문제 정의

기존 여행 서비스는 연령대, 지역, 자유여행/패키지 같은 일반 여행 기준으로 설계되어 있다. 반면 애니메이션, 아이돌, 게임, 영화/드라마 팬들이 원하는 "콘텐츠 기반 성지순례" 여행은 일반 여행 앱에서 제대로 다뤄지지 않는다.

코어 팬은 이미 방문하고 싶은 성지를 알고 있거나, 작품별로 정리된 블로그/커뮤니티 정보를 찾아본다. 하지만 장소가 여러 개일 때 이동 순서, 여행 기간, 예산, 주변 관광지를 함께 고려해 실제 여행 일정으로 만드는 과정은 번거롭다.

성지덕은 이 문제를 "성지 데이터 + 지도 + AI 일정 생성"으로 해결한다.

## 3. 핵심 가치 / 차별점

- 오타쿠/팬덤이라는 니치 타깃에 맞춘 여행 플래너
- 작품 선택만으로 지도에서 성지 스팟을 직관적으로 확인
- 성지 100% 중심 일정 생성 후, 사용자가 원할 때 일반 관광지를 추가
- 최소 입력 기반 UX: 작품, 기간, 예산, 출발지만으로 1차 루트 생성
- 사용자가 추가/제외한 장소를 반영해 AI가 일정 재조정
- 여행 후 인증샷, 방문 기록, 공유 기능으로 덕질 경험 확장

## 4. 주요 사용자 시나리오

### S-1. 작품 기반 성지순례 일정 생성

1. 사용자는 성지덕에 접속한다.
2. 첫 화면에서 지도를 본다.
3. 사용자는 작품 목록에서 `러브라이브! 뮤즈`를 선택한다.
4. 지도에 해당 작품의 성지 스팟이 표시된다.
5. 사용자는 여행 기간, 예산, 출발지를 선택한다.
6. AI가 가능한 성지순례 루트를 생성한다.
7. 사용자는 Day 1, Day 2 일정과 지도 경로를 비교한다.
8. 사용자는 마음에 드는 일정을 저장한다.

### S-2. 사용자 지정 스팟 반영

1. 사용자는 추천 루트를 확인한다.
2. 지도에서 추가로 가고 싶은 성지 또는 주변 스팟을 선택한다.
3. 사용자는 "이 장소 포함해서 다시 짜줘"를 요청한다.
4. AI가 이동 순서와 체류 시간을 재조정한다.
5. 사용자는 수정된 일정을 저장하거나 공유한다.

### S-3. 방문 인증 및 공유

1. 사용자는 여행 중 성지에 방문한다.
2. 방문한 스팟에 인증샷 또는 메모를 남긴다.
3. 여행이 끝난 뒤 방문 기록을 확인한다.
4. 사용자는 트위터/X 등에 공유할 요약 문구를 생성한다.

### S-4. 비회원/회원 차등

1. 비회원도 작품 선택과 1회성 일정 생성은 가능하다.
2. 일정 저장, 공유, 개인화 추천, 방문 기록은 회원가입 후 사용할 수 있다.

## 5. MVP 범위

| 구분 | MVP |
|------|-----|
| 콘텐츠 범위 | 애니메이션 중심, 대표 데모는 러브라이브! 뮤즈 |
| 장소 데이터 | 관리자 제공 시드 데이터 + 레퍼런스 링크 |
| 지도 | Mock 좌표 기반 2D 지도 UI. 실제 지도 API는 2차 |
| 입력값 | 작품, 여행 기간, 예산, 출발지 |
| 일정 생성 | 성지 중심 일정 자동 생성 |
| 일정 수정 | 사용자가 추가/제외한 스팟 반영 |
| 저장/공유 | 회원 일정 저장, 공유 링크 또는 공유용 텍스트 |
| 인증 | 자체 회원가입/로그인 |
| 관리자 | 사용자/일정/작품/성지/AI 사용 통계 |
| 예약 | 항공권/숙소 직접 예약 제외. 추천 조건 및 외부 링크만 제공 |

## 7. AI 활용 포인트

LangGraph 에이전트는 다음 흐름을 담당한다.

1. 사용자 조건 분석
2. 작품별 성지 후보 조회
3. 여행 기간/예산/출발지 기반 후보 필터링
4. 일자별 루트 생성
5. 사용자가 추가/제외한 스팟 반영
6. 일정 설명과 추천 이유 생성
7. 공유용 요약 문구 생성

AI는 장소를 임의로 만들어내지 않는다. MVP에서는 백엔드 DB의 시드 데이터를 기반으로만 루트를 생성한다.

## 8. 데이터 원칙

- 성지 데이터는 관리자 시드 데이터로 시작한다.
- 각 성지에는 참고 블로그/사이트 링크를 레퍼런스로 저장한다.
- 상용 서비스가 아니더라도 저작권 리스크를 줄이기 위해 MVP에서는 공식 장면 이미지를 직접 저장하지 않는다.
- 작품/장소 설명, 실제 주소, 좌표, 레퍼런스 링크, 추천 체류 시간 중심으로 관리한다.

10. 관리자 화면에서 통계 확인
