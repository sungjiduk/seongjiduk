# ADR-0001. 기술 스택 선정

- 상태: 승인 (Accepted)
- 날짜: 2026-06-29
- 개정: 2026-07-02 — DB를 PostgreSQL에서 MySQL로 변경, 클라우드를 AWS로 확정

## 맥락
요구사항상 Java 25+, Spring, LangGraph, DB 1종, Docker, 클라우드 1종이 필수다.

서비스 주제는 `성지덕 - 오덕후를 위한 성지순례 기반 AI 여행 플래너`로 확정했다. MVP는 애니메이션 성지순례를 대상으로 하며, 대표 데모 콘텐츠는 러브라이브! 뮤즈다.

## 결정
- 언어/프레임워크: Java 25+, Spring Boot (Security, Data)
- AI: LangGraph는 **Python 별도 repo/service(`sungjiduk/seongjiduk-ai`)**로 분리, 백엔드와 REST 연동
- DB: MySQL
- 클라우드: AWS
- 영속화: Spring Data JPA
- 지도/교통: MVP에서는 mock 좌표와 시드 데이터 기반. 실제 지도 API는 2차 범위
- 예약: MVP에서는 외부 링크 제공. 실제 항공권/숙소 예약 API는 2차 범위

## 근거
- LangGraph 생태계는 Python 중심 → 분리 시 기능/예제 활용 폭이 넓음
- MySQL은 여행 일정, 사용자, 성지 데이터를 구조화해서 저장하기 적합하고, 팀 숙련도와 레퍼런스가 풍부해 개발 속도에 유리하다
- JPA는 도메인 엔티티 중심의 CRUD와 관리자 기능 구현에 적합
- AWS는 RDS(MySQL) 매니지드 DB, EC2/ECS 배포, ACM 기반 HTTPS, CloudWatch 등 요구 제출물(배포·HTTPS·모니터링) 연동 생태계가 넓다

## 대안
- langgraph4j로 JVM 내장 → 단일 배포 단순하나 기능 제약
- PostgreSQL/pgvector → 벡터 검색에 유리하지만 MVP 필수가 아니고, 팀 숙련도를 고려해 MySQL을 채택. 벡터 검색이 필요해지면 별도 벡터스토어(Chroma 등)를 검토
- GCP/Azure/NCP → 요구사항 충족은 가능하나, 팀 접근성과 자료를 고려해 AWS 선택

## 결과 / 영향
- 컨테이너 최소 구성: backend, frontend, ai-service, mysql
- 운영 DB는 AWS RDS(MySQL) 사용을 우선 검토하고, 컨테이너 mysql은 로컬/대안용으로 둔다
- AI 서비스는 독립 repo/CI/CD를 가진다. 로컬 Docker Compose에서는 sibling checkout의 `seongjiduk-ai`를 build context로 사용하고, 운영에서는 `ghcr.io/sungjiduk/seongjiduk-ai` 이미지를 사용한다.
- 모니터링 제출을 위해 Prometheus/Grafana 추가 검토
