# ADR-0005. AI 설명 읽기 경로 보호 — 캐시 + single-flight

- 상태: 승인 (Accepted)
- 날짜: 2026-07-07

## 맥락
`GET /api/contents/{id}/spots`가 AI 설명을 병합한다. GPT 호출은 느리고(34곳 ~66초) 유료다. 실측에서 두 가지 누수를 확인:
1. 같은 성지를 재조회할 때마다 GPT 재호출.
2. 캐시가 비어 있을 때 **동시 요청**이 들어오면 전부 캐시 미스 → GPT **중복 호출** (React StrictMode 이중 fetch로 재현: describe 2회 = 비용 2배).

## 결정
1. **성지별 인메모리 캐시** (`ConcurrentHashMap<spotId, 설명>`): 같은 성지는 재호출 안 함. 서버 재시작 전까지 유효 — 상용화 시 DB 컬럼/TTL로 영속화(A파트 조율).
2. **작품별 single-flight 가드** (#39): `computeIfAbsent` 락 + **락 획득 후 캐시 재확인**(double-check). 첫 요청만 AI를 호출하고, 나머지 동시 요청은 락에서 대기 후 채워진 캐시를 읽는다.
   - "두 번째 요청은 건너뛰고 null 반환" 방식은 기각 — StrictMode에선 **두 번째 응답이 화면에 남아** 설명이 사라진다. 대기 방식은 어차피 첫 호출 완료 시간과 같아 추가 지연이 없다.
3. **실패 격리**: AI 미가용 시 설명만 null로 목록 정상 반환, 다음 조회에서 재시도 (실패는 캐시하지 않음).

## 검증
- BDD 동시성 테스트: 2스레드 동시 출발 + 300ms 지연 mock → RED "Wanted 1 time / But was 2 times"로 중복 재현 → 구현 후 `times(1)` + 두 응답 모두 설명 포함.
- **라이브 실측**: 프론트 fetch 2회 발사 → ai-service 수신 **1회** (수정 전 2회). 첫 로딩 GPT 비용 절반.

## 결과 / 영향
- 1차 조회 ~66초(GPT 생성) → 2차 조회 0.05초(캐시).
- seam: pre-warm(임포트 직후 백그라운드 생성)이 들어오면 사용자는 첫 조회부터 즉시.
