# ADR-0003. AI 레이어 구조 — LangGraph + 프로바이더 스위처블 + 역할 분리

- 상태: 승인 (Accepted)
- 날짜: 2026-07-06

## 맥락
AI는 "루트 계산기"가 아니라 **"말로 다듬는 파트너"**(장면 설명·제목·이유·개인화)로 쓴다. 좌표·순서 같은 사실 계산을 LLM에 맡기면 환각·불안정이 생기고, 반대로 언어 생성을 규칙으로 만들면 뻔해진다. 또한 팀원·CI는 OpenAI 키 없이도 개발·테스트가 가능해야 한다.

## 결정
1. **역할 분리 원칙: "LLM은 언어, 도구는 계산".**
   - 도구 노드(결정론): 스팟 필터링, Day 배치, 시간 배정, 좌표.
   - LLM 노드: 제목·Day 요약·방문 이유·공유 문구·장면 설명.
2. **LangGraph 그래프 2개** (seongjiduk-ai): `/ai/spots/describe`(장면 설명), `/ai/trips/generate`(도구 노드 → LLM 노드).
3. **프로바이더 스위처블**: `OPENAI_API_KEY` 있으면 GPT(langchain-openai), 없으면 **결정론적 mock**. 키·비용 없이 CI/로컬 테스트 통과, 키 주입 시 실동작 (지오코더와 같은 패턴).
4. **backend 폴백**: ai-service 실패 시 — trip은 로컬 배치 폴백, describe는 설명 null(목록은 정상 반환, 다음 조회 재시도).
5. **청크 분할 + 부분 폴백**: describe는 스팟 8개 단위(env `AI_DESCRIBE_CHUNK`)로 LLM 호출. 실패한 청크만 mock 폴백 — 한 번의 타임아웃이 전체를 망치지 않는다. (34스팟 단일 호출 → 30s 타임아웃 실측 후 도입)

## 근거
- 실측: 좌표·순서를 도구가 쥐고 LLM이 문장만 입히면 응답이 안정적이고 검증 가능.
- mock 폴백 덕에 시연·CI가 외부 의존 없이 항상 성립.

## 결과 / 영향
- 라이브 E2E 검증: describe 34/34 GPT 생성, trip 6.3초 생성(제목/요약/이유 + spotId 연결 + 제외 반영).
- seam: 이동시간(Directions)·솔버는 도구 노드 자리에 후속 추가.
