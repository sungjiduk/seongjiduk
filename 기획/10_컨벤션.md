# 10. 컨벤션 정의 문서 (제출물)

## Git
> 브랜치/커밋/PR 상세 규칙의 SSOT는 `11_Git_브랜치_PR_규칙.md`. 아래는 요약이며, 충돌 시 11번을 따른다.
- 브랜치: `main`(배포) / `dev`(개발 통합) / `feat/*` · `fix/*` · `docs/*` · `infra/*` · `chore/*`(작업)
- 커밋·PR 제목: `[TYPE] 한국어 한 줄 요약` 형식. TYPE = FEAT / FIX / DOCS / INFRA / CHORE / REFACTOR / TEST / PERF (대문자 + 대괄호)
- 소문자 Conventional Commits(`feat:`, `fix:` 등)는 **사용하지 않는다.**
- PR: base는 `dev`, 한 PR은 하나의 목적. 리뷰 1인 이상 승인 후 머지를 원칙으로 한다. (브랜치 보호 강제는 저장소 플랜 제약이 있어 현재는 팀 관례로 운영)

## 코드 (Java/Spring)
- 패키지 구조: (layered / domain 중 택)

- DTO/Entity 분리, Lombok 사용 범위 합의
- 포매터/린터: (예: Spotless, Checkstyle)
